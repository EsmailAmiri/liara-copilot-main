# Safety model

## Risk tiers
| Tier | Behavior | Examples (defaults; adjust after `pnpm probe`) |
|---|---|---|
| `read` | Auto-run, logged | list/get apps, logs, metrics, status, env **names**, plans, http probe, dns lookup, project analysis |
| `low` | Auto-run, announced in timeline, reversible/additive, no user-facing downtime | create empty app (`create_app`) |
| `high` | **Proposal only** → user approval required | deploy, restart, stop/start, set/update/delete env (restarts app), change plan/resources, domain/DNS changes, any delete |

`packages/tools/src/risk-policy.ts` is the single source of truth. Unknown tools default to `high`. Tools are evaluated via `classify(tool, args, ctx)`.

## Approval gate (server-enforced)
1. Agent calls a `high` tool → the tool **does not execute**. The gate creates a `PendingAction`:
   `{ id, conversationId, tool, args, argsHash, summary, impact, rollback, risk, createdAt, expiresAt, status }`.
2. The model receives `{status:"pending_approval", approvalId}` as the tool result and must tell the user it is waiting.
3. SSE emits `approval.required` with the card payload (generated by the tool's `describe()` — **not** by the LLM, so the card can't be misleading).
4. UI calls `POST /api/approvals/:id/approve|reject` (session-authenticated, CSRF-protected). Execution uses the **stored** args and re-verifies `argsHash`.
5. Rules: single use; expires after `APPROVAL_TTL_SECONDS`; rejected on hash mismatch; cannot be approved from an LLM-originated request; approval/rejection/execution all written to `audit_log`.
6. After execution the result is fed back to the agent, which must run `verify_fix` (when applicable).
Tests required: replay, expiry, tamper (args changed), cross-conversation approval, unknown tool → high.

## Secrets & data handling
- Token/keys only in server env. Never sent to browser, model, logs, or audit.
- `redact()` runs on all tool outputs: Bearer tokens, `password=`, connection strings (`scheme://user:pass@`), private keys, long hex/base64 secrets, **env values** (names kept; values replaced with `‹redacted›` unless key ∈ allowlist: `NODE_ENV, PORT, TZ, LOG_LEVEL`).
- Logs sent to the model are truncated (default last 200 lines / 20 KB) and redacted.
- UI auth: passcode → signed httpOnly session cookie (SameSite=Lax or None+Secure if cross-origin), login rate-limit, constant-time compare.
- `LIARA_APP_ALLOWLIST` limits which apps tools may touch.
- Prompt-injection: tool outputs (especially logs) are **untrusted data**. System prompt says so; the gate makes it harmless — injected text cannot execute `high` actions.

## Audit log
Every tool call (name, redacted args, tier, outcome, duration, traceId), every approval event, every alert. Viewable in UI (`/audit`) and exportable as JSON.

## Limitations to state in README and UI
Mock vs live; API gaps from the capability matrix; ephemeral storage; single-user; LLM can be wrong (cards show evidence; high actions need approval).
